# 🏥 Прогнозування витрат на медичні послуги нейронною мережею (PyTorch)

У цьому проєкті з нуля, на чистому **PyTorch**, побудовано повнозв'язну нейронну мережу, яка **передбачає, скільки людина витратить на медичні послуги**, за шістьма простими характеристиками: вік, стать, ІМТ, кількість дітей, куріння, регіон.

Нейронні мережі розв'язують два основні типи задач: **класифікацію** (визначити клас) і **регресію** (передбачити число). Тут розв'язується саме **регресія**: на виході мережі одне число — прогноз витрат.

Весь код написаний у Jupyter/Colab-ноутбуці, а нижче кожен крок розібрано: що робиться і чому саме так.

## Крок 2. Перетворення категоріальних ознак у числа

```python
# sex -> дві колонки sex_female / sex_male (one-hot)
df_sex_encoded = pd.get_dummies(df, columns=['sex'])

# smoker -> одна бінарна колонка is_smoker (1 / 0)
df_1 = df_sex_encoded.copy()
df_1['is_smoker'] = df_1['smoker'].map({'yes': 1, 'no': 0})
df_1.drop('smoker', axis=1, inplace=True)

# region -> чотири колонки region_* (one-hot)
df_2 = pd.get_dummies(df_1, columns=['region'])
```

Використано два підходи:

| Ознака | Метод | Результат |
|---|---|---|
| `smoker` | `map` (бінарна ознака) | `is_smoker` ∈ {0, 1} |
| `sex` | one-hot (`get_dummies`) | `sex_female`, `sex_male` |
| `region` | one-hot (`get_dummies`) | `region_northeast`, `region_northwest`, `region_southeast`, `region_southwest` |

One-hot кодування обрано для `region`, бо регіони **не мають порядку**. Якби закодувати їх числами 0, 1, 2, 3, мережа вважала б, що один регіон «більший» за інший.

Після кодування маємо **10 числових ознак**: `age`, `bmi`, `children`, `is_smoker`, 2 колонки статі й 4 колонки регіону.

## Крок 5. Масштабування ознак і цільової змінної, тензори

### Масштабування ознак `X`

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
X_train = scaler.fit_transform(X_train)    # вчимо скейлер ТІЛЬКИ на train
X_test  = scaler.transform(X_test)         # до test лише застосовуємо
```

Ознаки мають різні масштаби: вік — десятки, ІМТ — ~30, а `is_smoker` — 0 або 1. Після стандартизації кожна ознака має середнє 0 і стандартне відхилення 1. Так градієнтний спуск працює швидше й стабільніше.

**Уникнення витоку даних (data leakage).** `fit_transform` викликається лише на тренувальних даних, а на тестових — тільки `transform`. Середнє й відхилення обчислюються тільки за train, і жодна інформація про тест не потрапляє в навчання.

> ⚠️ **Примітка.** У ноутбуці ознаки `X` стандартизуються двічі: спочатку `scaler`, а потім ще раз `scaler_X` (у комірці перед створенням тензорів). Друга стандартизація вже стандартизованих даних практично нічого не змінює (середнє ≈ 0, відхилення ≈ 1), тож на результат вона майже не впливає, але вона зайва. Можна безпечно залишити лише один скейлер.

### Масштабування цільової змінної `y`

```python
scaler_y = StandardScaler()
y_train_scaled = scaler_y.fit_transform(y_train.values.reshape(-1, 1))
y_test_scaled  = scaler_y.transform(y_test.values.reshape(-1, 1))
```

Витрати вимірюються десятками тисяч, тому їхні квадрати в `MSELoss` — сотнями мільйонів, а градієнти виходять величезними. Стандартизація `y` приводить помилку до розумних значень і робить навчання значно стабільнішим. Скейлер для `y` також навчається лише на train. Він зберігається в `scaler_y`, щоб потім **повернути прогнози у справжні одиниці** через `inverse_transform`.

`reshape(-1, 1)` потрібен, бо `StandardScaler` очікує двовимірний масив `[N, 1]`, а не одновимірний `[N]`.

### Перетворення на тензори

```python
import torch
import torch.nn as nn

X_train_tensor = torch.tensor(X_train, dtype=torch.float32)
X_test_tensor  = torch.tensor(X_test,  dtype=torch.float32)

y_train_tensor = torch.tensor(y_train_scaled, dtype=torch.float32).view(-1, 1)
y_test_tensor  = torch.tensor(y_test_scaled,  dtype=torch.float32).view(-1, 1)
```

PyTorch працює з **тензорами**, а не з масивами NumPy чи таблицями pandas.

- `dtype=torch.float32` потрібен, тому що ваги мережі мають тип `float32`, і типи мають збігатися.
- `.view(-1, 1)` гарантує форму `[N, 1]`. Мережа повертає саме її, а `MSELoss` очікує однакові форми. Без цього з'явилося б небажане broadcasting, і помилка рахувалася б неправильно.

Форма тренувальних ознак — `(1070, 10)`: 1070 прикладів по 10 ознак.

## Крок 6. Архітектура мережі

```python
class MedRegression(nn.Module):
    def __init__(self):
        super().__init__()
        self.model = nn.Sequential(
            nn.Linear(10, 100),
            nn.ReLU(),
            nn.Linear(100, 50),
            nn.ReLU(),
            nn.Linear(50, 1)
        )

    def forward(self, x):
        return self.model(x)

model = MedRegression()
```

```
Вхід: 10 ознак
   │
Linear(10 → 100) ── ReLU
   │
Linear(100 → 50) ── ReLU
   │
Linear(50 → 1)
   │
Вихід: 1 число (прогноз витрат у масштабованому вигляді)
```

**Що тут важливо:**

- Мережа — це клас, що успадковує `nn.Module`. У `__init__` оголошуються шари, а в `forward` описується, як дані проходять через них. Метод `backward` писати не потрібно, бо PyTorch обчислює градієнти автоматично (autograd).
- **`nn.Linear(10, ...)`**: 10 на вході відповідає кількості ознак.
- **`nn.ReLU()`** між шарами додає нелінійність. Без неї кілька лінійних шарів зводилися б до одного, і мережа не могла б вивчати складні залежності.
- **Останній шар без функції активації.** Це задача регресії, і на виході потрібне довільне число. Якби тут стояла `Sigmoid` або `ReLU`, вихід був би обмежений. Для класифікації було б навпаки.
- Останній шар має **1 нейрон**, бо передбачається одне число.
- Усього в мережі **6201 навчальний параметр**: 1100 + 5050 + 51.

## Крок 7. Функція втрат і оптимізатор

```python
criterion = nn.MSELoss()
optimizator = torch.optim.Adam(model.parameters(), lr=0.001)
```

- **`MSELoss`** — середньоквадратична помилка. Це стандартний вибір для регресії: вона сильно штрафує великі промахи.
- **`Adam`** — адаптивний оптимізатор, який добре працює «з коробки». Йому передаються `model.parameters()`, тобто всі ваги, які потрібно оновлювати.
- **`lr=0.001`** — швидкість навчання, тобто розмір кроку градієнтного спуску. Це стандартне значення для Adam; воно менше, ніж 0.01, і тому навчання плавніше й стабільніше.

## Крок 8. Цикл навчання

```python
epochs = 600
model.train()

for epoch in range(epochs):
    optimizator.zero_grad()                    # 1. обнулити старі градієнти
    y_pred = model(X_train_tensor)             # 2. прямий прохід (forward)
    loss = criterion(y_pred, y_train_tensor)   # 3. порахувати помилку
    loss.backward()                            # 4. зворотний прохід (backprop)
    optimizator.step()                         # 5. оновити ваги

    if (epoch + 1) % 100 == 0:
        print(f"Епоха {epoch + 1}/{epochs}, Помилка: {torch.sqrt(loss):.4f}")
```

Це серце будь-якого навчання в PyTorch. Перед циклом `model.train()` переводить модель у режим навчання (для цієї мережі різниці немає, але це правильна звичка, бо `Dropout` і `BatchNorm` поводяться по-різному в режимах train та eval). За кожну епоху виконуються п'ять кроків:

| # | Рядок | Що відбувається |
|---|---|---|
| 1 | `optimizator.zero_grad()` | PyTorch **накопичує** градієнти, тому перед кожною ітерацією їх треба обнулити. Це стандартний спосіб: обнуляються градієнти всіх параметрів, які передані оптимізатору |
| 2 | `model(X_train_tensor)` | прямий прохід: мережа видає прогнози для всіх тренувальних прикладів |
| 3 | `criterion(...)` | порівняння прогнозів із реальними значеннями, отримуємо одне число — помилку |
| 4 | `loss.backward()` | автоматично обчислюються градієнти помилки за кожним параметром |
| 5 | `optimizator.step()` | Adam зсуває ваги в бік, що зменшує помилку |

### Що виводиться під час навчання

Кожні 100 епох друкується `torch.sqrt(loss)`, тобто **RMSE у масштабованих одиницях**. Це помилка, виражена в стандартних відхиленнях цільової змінної, а не в грошах. Тому значення мають бути невеликими (близько 0.4–0.5 і менше), а не десятки мільйонів, як було б без масштабування `y`. Щоб побачити помилку у справжніх одиницях, див. [Крок 9](#крок-9-оцінка-на-тестових-даних).

## Крок 9. Оцінка на тестових даних

```python
from sklearn.metrics import mean_squared_error, r2_score

model.eval()
with torch.no_grad():
    pred_scaled  = model(X_test_tensor).numpy()
    pred_dollars = scaler_y.inverse_transform(pred_scaled)

    rmse = np.sqrt(mean_squared_error(y_test, pred_dollars))
    r2   = r2_score(y_test, pred_dollars)

    print(f"Справжня помилка RMSE: ${rmse:.2f}")
    print(f"Точність R² Score: {r2:.4f}")
```

- **`model.eval()`** перемикає модель у режим оцінювання (парний до `model.train()`).
- **`torch.no_grad()`** вимикає обчислення градієнтів: під час оцінювання вони не потрібні, тож економляться пам'ять і час.
- **`.numpy()`** перетворює тензор назад у масив, щоб передати його в `sklearn`.
- **`scaler_y.inverse_transform(...)`** повертає прогнози зі стандартизованого вигляду у **справжні одиниці** (гроші). Порівнювати треба саме їх із `y_test`, який не масштабувався.
- **RMSE** — корінь із MSE. Він виражається в тих самих одиницях, що й цільова змінна, тому його легко інтерпретувати: це «типова помилка прогнозу».
- **R² (коефіцієнт детермінації)** показує, яку частку розкиду витрат пояснює модель. 1.0 — ідеальний прогноз, 0 — не краще, ніж завжди прогнозувати середнє.

## 📊 Результат


Як інтерпретувати:

- Щоб перевірити, що мережа **не перенавчилася**, порівняйте помилку на тесті з помилкою на тренуванні (обидві у справжніх одиницях). Якщо вони близькі, мережа працює на нових даних не гірше, ніж на тих, на яких вчилася.

## 💡 Що можна покращити

Проєкт навмисно залишено простим, щоб було видно основи. Наступні кроки для покращення якості:

- **Прибрати подвійну стандартизацію `X`** і залишити один скейлер.
- **Навчати міні-батчами** (`DataLoader`) замість усієї вибірки одразу.
- **Додати validation-вибірку та early stopping**, щоб автоматично зупиняти навчання в потрібний момент, а не за фіксованою кількістю епох.
- Спробувати **Dropout**, іншу кількість шарів і нейронів, інший `lr`.
- Порівняти з класичними моделями (`RandomForest`, `GradientBoosting`): на табличних даних вони часто не гірші за нейромережі.
- Зберегти навчену модель (`torch.save`) разом зі скейлерами й зробити просту форму для прогнозу нових даних.
